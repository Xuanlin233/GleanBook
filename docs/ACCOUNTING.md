# 业务规则与数据模型

## 金额与精度

- 所有金额、价格、份额、汇率以十进制字符串存储，使用 decimal.js 运算，精度 160 位。
- 原始输入最多 24 位整数、18 位小数；业务校验拒绝负消费、非法日期、缺失引用和多余字段。
- 人民币**只在展示时**保留两位，使用 ROUND_HALF_UP。原币明细和精确份额保留原始数值，绝不从展示值反推持仓。
- 图表坐标和百分比转成 JavaScript Number 仅用于绘制，不回写财务数据。金额显示不经过二进制 Number，避免大数丢精度。

## 日常账单

手动账户余额 = 期初余额 + 收入 + 退款 − 支出 − 独立手续费 − 转出本金 − 转账手续费 + 转入金额 + 投资结算净变动。

转账本金从不计收入或消费。同币种转入本金必须等于转出本金，手续费独立；跨币种必须填写两个原币金额。转账手续费按转出币种发生时人民币汇率计消费。

信用卡使用负债账户：消费时从该账户记支出，欠款增加；还款从银行转入负债账户，不重复算消费。期初欠款不计消费。账户变为正余额时，超额还款属于资产。

退款必须关联存在的同币种原支出，沿用原分类，累计退款不能超过原支出，发生时间不能早于原支出。退款在**退款发生月份**冲减该分类；允许当月净支出为负，不改写过去月份已经发生的消费。有关联退款时不能直接删除原支出。

历史非人民币收支保存当时的 CNY/原币汇率，不因当前估值汇率变化重算。没有可靠历史汇率时，用户必须填写，不默认为 1。

修改或删除账单时，从全部原始记录重新派生余额和对应月份统计，无需手工反冲。删除被引用的账户、分类和持仓会被拦截。

## 投资持仓

日常账单和投资事件分别保存。持仓的期初数量是**既有资产**，不扣现金，不算收入；必须确保录入的现金账户余额未包含这份投资，避免重复。

投资事件按时间、稳定 ID 排序，采用**移动加权平均成本**：

- 买入：现金扣成交金额与手续费；数量增加，成本增加成交金额与手续费。
- 卖出：现金入成交金额减手续费；减少数量与对应平均成本，已实现收益 = 成交金额 − 手续费 − 售出成本。
- 现金分红：现金增加净分红，记入投资已实现收益，保留持仓成本；不计生活收入。
- 份额调整：调整数量，保持总成本不变。适合拆分、合并、更正数量；不适合新增现金本金。
- 赚币利息：数量增加，新增份额成本为 0；单独展示利息数量。收益的人民币金额受价格和汇率影响，没有擅自假定每天利息金额。

例：100 份成本 100 元，买入 100 份支付 120 元、手续费 2 元，平均成本 1.11 元/份。卖出 50 份取得 65 元、手续费 1 元，已实现 8.5 元，剩余成本 166.5 元。

期初成本未填写时保留 null，显示“成本待补充 / 收益暂不可计算”，不显示强制零收益。期初成本一旦未知，后续仅有部分交易也不足以准确重建全部成本。

待确认申购先扣现金，持仓内暂计等额待确认本金，手续费减少净资产；确认后按正式份额改成市值。待确认赎回仍计入持仓，限制不能重复预约超量份额，确认后才入现金并扣份额。确认对原事件进行更正，采用原记录结算日期；如果实际结算日期不同，请删除原草稿并按确认单日期重新录入。未实现基金订单全流程与逐日结算重建。

当前不提供“我的当日持仓收益”指标，也不把市场 24 小时涨跌当作持仓收益。新增本金、充值提现和转账不算投资收益。未实现跨币种税务损益或完整币币交易成本流水。

## 估值、负债与不完整数据

- 基金市值 = 精确份额 × 单位净值。
- 其他持仓市值 = 数量 × 单位价格，再按计价币种独立换算 CNY。
- 现金与投资分开汇总；负账户余额归入负债，净资产 = 资产 − 负债。
- USDT 单位资产可使用 1 USDT / USDT 的同币种单位价格；这不意味着 1 USDT = 1 USD。USDC-USDT 则使用真实市场价格。
- 缺少价格或汇率的非零持仓**不计入已知小计，并明确提示缺少哪些项目**，不能把小计称为完整总资产。
- 最近成功价格不会因请求失败被清空；旧数据按原时间显示。市场价超过 15 分钟、基金净值超过 5 天提示“数据较旧”。汇率超过 7 天提示较旧。这里是提示阈值，不承诺交易日和发布时间日历准确。官网实验接入保留独立的上海净值日，不把获取日当作净值日。

## 外部快照与对账

外部余额和手动账本是两种来源。外部账户余额只使用最近快照，生活账单可以统计但不再次扣余额；本地转账和投资结算不能修改同步账户。

OKX 以 `资金/交易/活期赚币 + 原币` 为稳定标识。资金用 bal，现货交易用 cashBal，赚币用 amt，绝不把 loanAmt、pendingAmt 加到 amt，也不把累计 earnings 再作为新增资产。

接口读取不是跨账户原子快照。读取顺序中任何失败、不安全权限、非现货模式下存在未平仓杠杆 / 合约 / 期权仓位、负余额、明确借贷/隔离余额、明确赎回中余额或过大时间差都会终止本次更新。全部成功仍需人工对照 App 总览：接口未返回字段无法证明没有在途或未覆盖产品。

导入替换上次外部快照，不生成收支或投资交易，避免重复扣减。不自动获取历史，不声称收益完整。不自动清除已有手动持仓，导入前要求核对并移除相同的手动项。同步后的基金或 xStock 覆盖不能仅凭 App 出现推定。

## 定投计划

计划包含来源（手动现金账户，或手动持仓）、去向（手动持仓）、频率（每天 / 每个工作日 / 每周 / 每两周 / 每月，31 日在小月取月末）、精确到分钟的执行时间（按计划时区）、开始与可选结束日期。每期两种口径二选一：

- **定额**：每期固定扣款金额（含手续费），币种可选来源或去向币种；份额 = 净额 ÷ 当期价格。
- **定份额**：每期固定买入数量；扣款 = 数量 × 当期价格 + 手续费，币种为去向持仓币种。

手续费按外扣法：净额 = 金额 ÷ (1 + 费率)，手续费 = 金额 − 净额。基金份额截断到 0.01；加密数量截断到 8 位小数；法币金额四舍五入到分。来源为持仓时按当期来源价格卖出足额单位（向上取整）。来源与去向币种不同时按设置中的 CNY 汇率换算并在记录里锁定。

可选“节假日不扣款”：执行日不是沪深交易日（周末、法定节假日，以及调休上班的周六周日）时跳过这一期，不顺延、不补扣；未勾选时照常生成，基金在节假日下单按下一交易日净值成交。节假日依据国务院放假通知，取自 holiday-cn 公开数据（jsDelivr 与 GitHub 镜像，免费无需 Key）。下一年安排公布前，该年工作日的期数暂缓生成，公布后从暂停处继续补记。已公布年份缓存在当前浏览器，离线时也可判断。

没有后台服务：每次打开或刷新网站时，生成截至当前所有到期的期数（开始日期早于今天会补记）。每期快照计划条款，之后编辑计划只影响新期数；暂停后恢复从当时继续，不补记暂停期间；删除某一期后不会再生成。

成交价格：

- 基金：15:00 前用当日正式净值，15:00 及以后用下一交易日净值；周末和节假日顺延到下一个有净值的交易日。净值公布前该期为“待处理”。
- 加密资产（`*-USDT`）：OKX 现货在执行时间那一分钟的 1 分钟 K 线开盘价，必须时间戳完全吻合且已收盘。
- 与计价币种相同的资产（如 USDT 计价的 USDT）单位价格为 1。其他资产无法自动取价，每期需手动确认。

定额且来源为现金账户的期数，到期即扣款并计为去向的待确认本金；其余期数在价格确定后同时扣减来源、增加去向。会导致来源持仓不足等校验失败的期数保持待处理并显示原因，不影响其他期。任一期可按平台实际确认单手动修改，手动确认后不再自动取价。定投去向和来源不能是 OKX 只读快照项目，避免与同步余额重复。

## 订阅

总览页的“订阅”记录固定扣费的软件与会员：名称、扣款账户（任意手动账户，含信用卡等负债账户）、每期金额（账户币种）、周期（每月 / 每年 / 每周）、扣款日、支出分类（默认新建“订阅服务”）、开始与可选结束日期。

到扣款日当天 0 点（统计时区）起，打开或刷新网站时自动记一笔支出，备注“订阅自动扣款：名称”，计入当月消费、分类统计与预算；离线也会记账。开始日期早于今天会补记已到期的各期。每月 31 日在小月取月末，每年 2 月 29 日在平年取 2 月 28 日。外币账户按当时的人民币汇率记账；缺少汇率时暂缓扣款，补齐后再记。已记的扣款是普通账单，可在账单页修改或删除，删除后不会被补回。暂停后恢复从当时继续，不补记暂停期间；删除订阅保留已记账单。面板顶部的“每月约”按年付 ÷ 12、周付 × 52 ÷ 12 折算并换成人民币，暂停的订阅不计入。

## 快照、时区与数据升级

默认统计时区 Asia/Shanghai。日、月边界都经过该时区转换；设备输入时间仍按设备本地时区解释并存为 UTC ISO 时间。更改统计时区时需明确确认，边界附近账单可能更换日期或月份。

在打开、刷新、本地数据修改时记录快照。同一统计日、同一时区覆盖为最新观测；不补齐缺失日期。另有“今日”分时曲线：每次净资产或估值完整性变化记一个点（同一分钟内只保留最后一次），只保留最近 48 小时；按天的历史不足两天时默认显示今日曲线。估值不完整的点不绘制。图表只使用当前时区内完整估值快照，只有一个点时显示单点，零点时显示空状态。快照是当时观测，修改历史交易不会倒推历史市场价格或重写旧观测。

IndexedDB 版本 1，账本 schemaVersion 1。整本账本在单次 IndexedDB 事务内保存，通过 revision 检查防止多窗口静默覆盖，BroadcastChannel 通知其他窗口；未提交表单仍在当前窗口。多窗口同时编辑同一记录属于最后一次明确提交覆盖，不存在云冲突合并。

升级方案：未来每次新增 schemaVersion，先将旧结构复制并逐版本执行纯迁移函数，完整校验成功后在同一 IDB 升级事务替换；失败回滚保留旧版本。当前没有虚构 v2 迁移；未知版本和旧格式都会拒绝写入，避免误解析损坏数据。上线有破坏性结构变更前必须先实现对应迁移与回滚测试。

JSON 导入只接受严格的拾账完整备份。预览后选择合并或覆盖；合并以稳定 ID 去重，同 ID 不同内容拒绝自动合并。不同 ID 的相似交易保留，避免误判真实的重复购买；不支持任意 CSV 自动导入。失败导入不会部分提交。
