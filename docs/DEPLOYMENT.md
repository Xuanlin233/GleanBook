# 部署与安全配置

## 方案 A：仅本地账本的静态 PWA

在 Windows 执行 `npm ci`、`npm run build`，将 **dist 文件夹内的内容**上传到 HTTPS 静态托管。应用只支持站点根路径部署，不能直接放在 `/subpath/`。使用 hash 路由，所以页面导航无需复杂重写规则。

示例：Cloudflare Pages 直接上传，需要注册 Cloudflare 账号。上传构建后的 dist，不要上传项目源码、node_modules、.env 或备份。`public/_headers` 已复制到 dist，适用于支持此格式的平台。

静态路线提供完整账本、手动资产、预算、JSON 恢复、CSV 导出、安装和离线能力。**本项目 Node 接口不能直接在 Pages 运行**；公共行情、后端验证和私人同步不可用时，会提示失败或未连接，不影响手动使用。没有伪造后端或调用私有接口的客户端降级路径。

网址可以公开分发应用壳，但账本只在各自浏览器设备存储，不通过站点链接共享。若连应用壳也需要限制访问，请使用托管平台的访问控制。访问控制、认证跳转是否能与 iOS 离线 PWA 配合，需要部署后验证。

## 方案 B：Node 24 同源服务

在支持长期运行 Node.js 的主机，设置构建命令 `npm ci --include=dev && npm run build`，启动命令 `npm start`。生产服务只读取 dist 和 server，不读取源码目录中的财务文件。也提供 Dockerfile；镜像构建未在当前 Windows 环境验证。

部署平台示例为 Render Web Service，需要注册账号并上传源码或连接代码仓库。需要为主机安全设置环境变量：

| 名称                     | 用途                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------ |
| `NODE_ENV=production`    | 强制后端会话 Cookie 使用 Secure；必须部署 HTTPS                                      |
| `HOST=0.0.0.0`           | 云端监听；Windows 本地默认 127.0.0.1                                                 |
| `PORT`                   | 使用托管平台分配的端口；本地默认 8787                                                |
| `APP_ORIGIN`             | 精确站点 origin，例如 `https://你的域名`，无末尾斜杠；本地例 `http://localhost:8787` |
| `GLEANBOOK_ACCESS_TOKEN` | 随机生成的至少 32 字符后端访问口令，不使用 OKX 密钥或交易账户密码                    |
| `OKX_API_KEY`            | OKX 只读 API Key                                                                     |
| `OKX_API_SECRET`         | 仅后端保存的 Secret                                                                  |
| `OKX_API_PASSPHRASE`     | 仅后端保存的 API Passphrase                                                          |
| `OKX_API_ORIGIN`         | 账号适用的 OKX 官方地区域名                                                          |

不使用任何 `VITE_` 变量存储私人凭证。Vite 变量会进入前端构建，不能存放密钥。

纯本地开发时可复制 `.env.example` 为 `.env`，只在本机安全填写。Node 24 启动时读取 .env，文件已被 Git 和 Docker 构建上下文排除；云部署优先使用平台 Secrets / 环境变量界面。不要把实际密钥粘贴到聊天、提交源码、写日志或上传备份。密钥不会返回浏览器，Service Worker 完全跳过 `/api/`。

后端访问口令通过设置页的密码输入发送到同源后端，验证成功使用 HttpOnly、SameSite=Strict 会话 Cookie，8 小时有效；浏览器不保存明文口令。会话保存在服务器内存，服务重启需重新验证。退出会话不删除本地账本与已确认的外部快照；私人 API 响应从未进入离线缓存。

所有私人接口要求会话；写入口还验证 Origin；登录与请求有频率限制。当前设计面向**单人、单实例**，不是多租户账号系统。多实例部署需要共享会话与限流；反向代理不得把外部可伪造头直接作为鉴权依据。服务器不信任 X-Forwarded-For，默认按直连地址限流，代理后可能合并限流，属于可用性限制。

## OKX 只读配置流程

1. 在本人账号创建 API Key，仅勾选 **Read**，关闭 Trade 和 Withdraw。建议绑定后端固定出口 IP；免费主机不一定提供固定出口 IP，使用白名单前先核对平台。
2. 按**账号注册地区**选择域名，不能仅凭你当前所在地或浏览器时区判断。官方当前文档说明：全球接口 `https://openapi.okx.com`，美澳注册账号 `https://us.okx.com`，欧盟注册账号 `https://eea.okx.com`。后端仅接受这三个及 `https://www.okx.com` 官方域名，拒绝任意 URL，避免凭证外发。
3. 在主机 Secrets 配置三个凭证与独立访问口令。不要发送给开发聊天。
4. 打开设置 → 数据连接，填写**独立后端访问口令**，验证后端。
5. 读取快照前，后端用 `/api/v5/account/config` 检查 `perm` 恰为 `read_only`、`acctLv` 不是现货模式 1 时再用 `/api/v5/account/positions` 确认没有未平仓仓位。不满足就停止，不发起交易或提币。
6. 依次读取资金余额、交易余额、活期赚币。核对 App，总额、申赎中的归属、手动重复项、未覆盖 xStock 或其他产品。不要在账户间划转过程中导入。
7. 预览核对后确认覆盖；缺价格或汇率的产品仍标示不完整，不显示虚假的“所有资产已同步”。

当前未提供真实私人凭证，因此端点结构与安全限制已实现，但**真实账号、地区差异、现货现金与赚币分项的账户级覆盖尚未验收**。这一步不可用时继续手动维护，不要升级权限来解决。

## iPhone、iPad 与 Windows 安装

- Safari 打开生产 HTTPS 地址，分享 → 添加到主屏幕；如果出现“作为网页 App 打开”开关，打开它。
- iPhone 第一次打开需联网等待缓存完成。随后可以断网记录；联网后数据仍只在此设备，**不会自动上传**。
- Windows Edge / Chrome 通过地址栏安装。localhost 可测试 Service Worker；手机通过 HTTP 局域网 IP 打开通常不能启用，必须使用 HTTPS 部署。
- Safari 浏览器和主屏幕 PWA 的存储行为、系统回收策略会因版本不同而变化；不要假设安装后账本必然共享，必要时用 JSON 迁移。
- 不要清理网站数据。浏览器持久存储申请不是永久备份。定期把 JSON 存到其他设备或可信存储，注意文件未加密。

## 发布更新与回滚

每次 `npm run build` 根据构建内容生成版本化 sw.js，缓存仅包括公共应用壳、JS、CSS 和图标。不缓存 API 请求、私人余额响应或密钥。

新 Service Worker 安装后等待，页面显示“更新应用”。有弹窗时按钮禁用，请先保存或关闭表单；记账草稿存入独立 IndexedDB 键。确认更新才发送 SKIP_WAITING 并刷新，不自动丢弃输入。其他表单需先保存，未实现跨刷新恢复所有类型表单。

回滚时重新部署原来的完整 dist。服务端 HTML / sw.js 使用 no-cache，哈希资源使用 immutable。不要只替换某个 JS 文件；旧版数据结构必须兼容，结构降级要先导出备份。当前只有 schemaVersion 1。

## 尚未部署的能力

没有后端数据库、用户隔离、跨设备同步、定时每日账本快照、交易历史抓取、自动备份或数据冲突合并。这些功能需要后端账本授权存储、鉴权、定时调度、成本和隐私设计后才能实现。当前未把设备上的账本或所有持仓上传到服务器。
